## Rules and standards

Each line ends with its source; a double-quoted clause is verbatim from that source. Quote the rule, not a paraphrase, when the conductor asks "what is the rule".

**Run state and envelopes**
- The run file is created at [1] and "you are its only writer"; every agent envelope is recorded verbatim the moment it returns; one `log.jsonl` line per phase, `wall_s` real and required, `tokens` `null` in-run; "On start, if a run file already exists for this idea/key, RESUME from the first incomplete phase — never restart from [1]". (.claude/commands/new-task.md §Run state — the conductor's memory lives on disk, not in your head)
- "Validate after every write." — after each Edit that appends an envelope, `jq . tasks/runs/<KEY>.json > /dev/null`; a failed parse stops the phase (NEARS-1478). `fix_in_run[]` and `consults[]` are TOP LEVEL, alongside `decisions[]`/`trail[]`/`sessions{}`, "never inside `phases{}`"; `qa.ac_table[]` = `{ac, status: PASS|FAIL, evidence}` and `review.findings[]` = `{id, file_line, severity, raised_by, status: open|resolved}` live inside `phases`. (.claude/commands/new-task.md §Run state — the conductor's memory lives on disk, not in your head)
- Shared envelope `{phase, agent, verdict, summary≤3 lines, artifacts[], qa_points[], contract_impact: yes|no|n/a, followups[], drift[], confidence?}`; verdicts `READY|MISSING` (checkers) · `PASS|FAIL` (QA) · `PASS|FINDINGS|BLOCKED` (reviewers) · `DONE|BLOCKED` (engineers) · `NEEDS_DECISION{question, options, recommendation}` for anyone — a technical one goes to the domain advisor first (Tier A), only a Tier C item to the owner; `BLOCKED{why}` covers a missing tool, "never guessed around". (.claude/commands/new-task.md §Shared envelope — every agent returns exactly one)
- The four [7] reviewer records use exactly the keys `code_reviewer` · `security_reviewer` · `contract_sync` · `ux_review` under `phases["7"]` — "Anything else silently blinds the board." (.claude/commands/new-task.md §[7] Review fan-out)

**Lanes**
- Lane enum `micro|express|tooling|no-runtime|full`, decided by the TL at [2]; express runs [6]→[7]→[8]→[10 only if a closed-list contract changed]→[9]→[9b]→[11] and "Gates are NEVER skipped: code review and live QA always run." (.claude/commands/new-task.md §Lanes — the Team Lead decides at [2]; .claude/skills/shared-rules/lane-definitions.md)
- tooling = confined to `scripts/` and/or `.claude/`, executes, no device surface, carries its own runnable self-test which IS the [8] QA and is recorded in `phases["8"]`; "No runnable self-test → NOT tooling: full." no-runtime = no executable surface, QA = N/A stated, still a [6] build. (.claude/skills/shared-rules/lane-definitions.md §tooling; .claude/commands/new-task.md §Lanes — the Team Lead decides at [2])
- Tripwires: micro >1 logic file OR >~50 changed lines OR any contract touch; express >2 logic files OR >~150 changed lines OR >1 component → auto-escalate, work preserved; `/new-task --lane micro|express|tooling|no-runtime|full` "is always honored". (.claude/skills/shared-rules/lane-definitions.md §micro, §express; .claude/commands/new-task.md §MICRO FLOW (lane: micro — replaces phases 1-11))

**Pre-flight**
- `orphaned-run-check.sh <KEY>` runs before the claim-check when a run file already exists: `ORPHANED` (exit 10) → RESUME from the first incomplete phase; `MERGED_STALE_RECORD` (exit 3) → close out the record, never resume; `NOT_FLAGGED` (exit 0) → proceed; exit 2 is not a verdict. (.claude/commands/new-task.md §Pre-flight — orphaned-run check (conductor, at run/session start, before [1]))
- Claim-check, five signals of unequal strength stated as "convergence, not proof": run file · `git branch -a --list '*<KEY>*'` · `git worktree list | grep <KEY>` (necessary, not sufficient) · Jira status (cannot attribute a write — every git and Jira write on this host is one identity) · Jira comments, "the load-bearing signal". "If claimed: STOP, report to user, do not race." `git log --grep` takes the full key `NEARS-1738`, never the bare number (NEARS-2025). (.claude/commands/new-task.md §Pre-flight — claim-check (conductor, before [1]))

**Advisors and tiers**
- The conductor is the ONLY asker: no phase agent holds `SendMessage`/`ListAgents`; an advisor holds no Write and no Bash. "Pilot rule (design §12): every consult point is OPTIONAL." — a skip is `advisor_skipped{phase, reason}` in `trail[]`, a timeout is `advisor_timeout{qid, advisor}` in `drift[]`; "Never wait past the budget." (3 min, 5 min at [8]). Advisor absent → `bash scripts/advisors/up.sh <name>` ONCE, else skip. Tier gates ([2b] here, [3] in `/run-sprint`) are fail-closed: retry once, then an interactive owner ask; never `advisor-decided` for a decision nobody made. (.claude/commands/new-task.md §Advisors — standing read-only domain sessions)
- Tiers: A = the domain advisor, answered in-run, `consults[]` + `decisions[]`, no owner action; B = `advisor-product` decides, owner ratifies later via a ticket comment (qid, question, decision, advisor, reply path) + label `advisor-decided`; C = "the owner only" — status Blocked + `waiting-on-owner` + the park comment, worktree and run file kept, resume from the recorded phase. Which item sits where is design §10, cited never restated; owner queues `bash scripts/advisors/owner-queue.sh`. (.claude/commands/new-task.md §Advisors — standing read-only domain sessions; tasks/advisors/00-advisors-design.md §10)

**/run-sprint**
- "A ticket is a HYPOTHESIS, not a spec": a ticket closing with zero code because its premise was falsified is a SUCCESS; "Never widen scope, never bend the code, to make an AC pass." (.claude/commands/run-sprint.md §A ticket is a HYPOTHESIS, not a spec)
- [1] COLLECT only tickets at the profile's ready-to-dev status (Ready) → [2] PLAN by, in order: `is blocked by` links · `contract_impact` backend before app · same files → different batches · no dependency → earliest; persist `plan.dependency_edges` (NEARS-2560); sizing line `N tickets → B batches at parallel_cap=C (serial floor = F batches)` → [3] APPROVE: "NOTHING runs before explicit approval"; an in-epic plan is Tier B (`advisor-product`, `approved_by: "advisor-product (<qid>)"`), outside the epic Tier C; `--dry-run` stops here → [4] RUN → [5] REPORT as ONE Jira comment on the epic. (.claude/commands/run-sprint.md §[1] COLLECT; §[2] PLAN; §[3] APPROVE; §[5] REPORT)
- [4]: one subagent per ticket whose FIRST action is `Skill(skill:"new-task", args:"<KEY>")` (or `run-team` only when `--team` is set); "Never fold two tickets into one conductor/coordinator, one run file, or one worktree." `--parallel N` default 1, standing ceiling 2, `N > 2` needs an OWNER GRANT recorded as `parallel_cap` + `approved_by` and re-read on resume. Per-ticket start gate: a non-empty `dependency_edges[<KEY>]` gates on exactly those keys; a missing map or `[]` fails closed to the whole-batch rule; re-verify each dep's live state at gate time; rebase base = the dep's `merged_tip` (latest by wall-clock merge time), never the sprint-start tip. (.claude/commands/run-sprint.md §[4] RUN — batch by batch)
- Pause-and-ask triggers, routed by tier: `NEEDS_DECISION` (technical = Tier A through the per-ticket conductor; Tier C → park) · QA cap-2 → park · merge-sentinel BLOCKED (trivial = Tier A, semantic = Tier C park) · a batch blocker failed → park only its declared dependents · PREMISE FALSIFIED → pause and ask, never widen. The runner never calls `transitionJiraIssue`, never invents or re-scopes tickets, and "You may never decide, ON YOUR OWN, to hand-spawn the workflow's phase agents" — a direct owner instruction is never a violation. (.claude/commands/run-sprint.md §[4] RUN — batch by batch; §Hard rules)

## Known traps

Rule ids taken from review-lessons.json (status active, case-insensitive, `scope` under `workflow/`): phase-output-not-committed-before-reap, envelope-shas-die-on-rebase-verify-by-content, conductor-manufactured-premise-downstream-of-correct-artifact, reviewer-git-stash-near-miss-shared-stack, ledger-write-verify-by-id-set-difference, a-safeguard-carries-its-own-ambiguity, git-status-cannot-prove-an-agent-wrote-nothing, an-enumeration-reads-like-a-measurement, device-free-space-is-the-fastest-moving-fact, a-chain-verified-within-one-layer-proves-nothing-about-reachability.

- **phase-output-not-committed-before-reap** (workflow/phase-contract, NEARS-1748) — a phase that PRODUCES FILES must end by committing them; the [11] reaper takes anything uncommitted and `git worktree prune --keep` has already failed cross-session; check `git status --porcelain` in the worktree at the END of every file-producing phase, not at merge time. (docs/workflow/review-lessons.json)
- **envelope-shas-die-on-rebase-verify-by-content** (workflow/merge-forensics, NEARS-1748/1749) — a rebase gives every commit a new identity while the old shas survive as dangling objects that still resolve; transfer a QA PASS or review verdict by CONTENT (blob hash of the merged file vs the tested revision), never by sha equality; when a reviewed sha moves, filter the delta to non-comment non-blank lines AND re-run the tests at the new tip anyway; record the MERGE COMMIT at [11]. (docs/workflow/review-lessons.json)
- **conductor-manufactured-premise-downstream-of-correct-artifact** (workflow/phase-packets, NEARS-1749) — a packet must not assert behaviour the conductor did not read at the implementing line; correct counts fused into a wrong composition sent two reviewers to disprove a phantom; before shipping a packet ask "which line makes this true?" and paste it. (docs/workflow/review-lessons.json)
- **reviewer-git-stash-near-miss-shared-stack** (workflow/git-safety) — the stash stack is REPO-GLOBAL while working-tree changes are per-worktree; a concurrent `git stash pop` pulls a stranger's churn in; the safe substitute for a clean tree is a throwaway `git worktree add`, never a stash. (docs/workflow/review-lessons.json)
- **ledger-write-verify-by-id-set-difference** (workflow/ledger-hygiene) — every write to `docs/workflow/review-lessons.json` is verified by set(ids at HEAD) − set(ids in working) == EMPTY and len(rules) == len(set(ids)), never by a rule COUNT; the file is routinely foreign-dirty, so a pre-edit snapshot diff is weaker and does not replace it. (docs/workflow/review-lessons.json)
- **a-safeguard-carries-its-own-ambiguity** (workflow/verification-design, NEARS-1749) — a check added to remove an ambiguity inherits all the trust of the check it guards; a control whose false-negative is indistinguishable from the fault inverts the discrimination; "ASSERTIONS SHOULD BE TIGHT, CONTROLS SHOULD BE LOOSE" — make a control as coarse as the discrimination allows. (docs/workflow/review-lessons.json)
- **git-status-cannot-prove-an-agent-wrote-nothing** (workflow/agent-recovery, NEARS-1749) — `git status --porcelain` is structurally blind to gitignored paths such as `docs/qa-evidence/*`; probe with `--ignored <path>`, `ls`/`find` and an mtime window across the agent's lifetime; absence at the published destination is not absence at the source. (docs/workflow/review-lessons.json)
- **an-enumeration-reads-like-a-measurement** (workflow/evidence-standards, NEARS-1749) — a table with one INFERRED row inherits the credibility of its verified rows; a claim about what a call site PASSES requires tracing the assignment; when proving absence mark each row OBSERVED or INFERRED; three agents sharing a shortcut agree three times and are wrong three times. (docs/workflow/review-lessons.json)
- **device-free-space-is-the-fastest-moving-fact** (workflow/qa-devices, NEARS-1749) — never quote a device free-space figure from a packet or profile; re-measure at acquisition and before scoring; a partial install from space exhaustion presents as the stale-APK class and reads as "the fix did not work". (docs/workflow/review-lessons.json)
